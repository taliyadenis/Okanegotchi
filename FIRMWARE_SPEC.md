# Complete firmware scope

The unchanged mvp schemas/protocol supply wire-level truth. This file specifies implementation architecture and fills local behavior gaps without changing the API.

## Architecture and build

Arduino C++ on ESP32-S3; portable core C++17 with no Arduino/FreeRTOS includes. App task alone owns UI/domain state. Network worker returns owned bounded responses via queues; does not draw or mutate pet state. SPI has exactly one execution owner or a documented mutex per short bus operation, never held during network waits. NFC polling must be bounded/asynchronous; do not hold the bus across an entire card wait. UI target 20 fps, input scan <=10ms and feedback target <=100ms; measure actual maxima on hardware. These are acceptance targets, not measured claims.

Use Adafruit ST7789/GFX, PN532/BusIO, ArduinoJson, Arduino-ESP32 WiFi/NetworkClientSecure/HTTPClient/Preferences APIs. Verify/pin actual working versions, including LEDC signatures of the selected ESP32 core. Configure hardware SPI with explicit SCK=12, MISO=13, MOSI=11. Both CS HIGH before initialization. Drivers must restore correct bit order/speed/mode per transaction (PN532 LSB-first; display MSB-first). Avoid nested incompatible beginTransaction wrappers around a library already managing transactions. No I2C Wire path and no software-bitbang replacement of the agreed shared hardware bus.

Profiles: primary Waveshare ESP32-S3-Zero FH4R2, 4MB flash/2MB QSPI PSRAM. Verify FQBN option names with installed Arduino CLI board details rather than guessing. Record flash partitions, USB CDC and PSRAM settings. No OTA requirement. If existing PlatformIO project is already proven, preserve it and document reproducible equivalents. Probe/report PSRAM at boot, support reduced-buffer operation when allocation fails. TLS/internal heap and task stacks are separate from PSRAM; measure free/min/largest heap and stack watermarks. Never claim 2MB PSRAM solves all internal memory limits. Record compiled sketch and partition space; leave room for final art and show projected asset budget separately.

No services required for host build. Real firmware source includes complete networking, not a TODO hidden by a mock flag. Production build and explicit `OKANEGACHI_LOCAL_DEMO` build must both compile. Local demo renders an unmistakable label, uses a separate storage namespace and cannot silently become a fallback claiming cloud success. It must not mix synthetic pending events with production state.

## Inputs, UI and audio

Active-low GPIO4/5/6 to ground, INPUT_PULLUP. Four-legged tactile switches still present only two electrical nodes. Debounce 25ms stable input. Long event once at >=1000ms after debounced press; short event only on debounced release if no long event. No autorepeat. Handle timer wrap, held-on-boot and simultaneous buttons deterministically (ignore startup-held until released; process same-tick events A/B/C). No surprise factory reset chord.

Pages cycle Pet -> Goal -> Check-in -> Menu. A short previous, C short next. A long home/back. B short selects, or pats on Pet. B long on Pet requests review; B long on Review confirms only the displayed valid frozen receipt. C long from Pet starts Catch-a-Star. Menu: review/play/connection/mute. Render hints, pending/offline/freshness, null goal/no budget, long names/truncation, date window and source label. UTF-8 strings validate by schema character limits, allocate bytes safely (up to 4 bytes/codepoint + terminator) and render unsupported glyphs as a visible fallback without corrupting buffers. Never copy remote strings with unchecked strcpy or printf-format them. Format USD from integer cents, no floating money math; wide intermediate for progress percentage and clamp rendered bars while preserving amounts.

Audio GPIO7 -> REQUIRED 1k -> passive piezo -> ground. PWM/LEDC tone scheduler, no busy delays. Quiet short cues for tap/confirm/celebrate/error; initial output LOW, return LOW after tone/mute. Muting persists on change only. Missing piezo is nonfatal. A piezo makes sound; don't advertise vibration motor feedback.

Catch-a-Star lasts 15s, 3 lanes; A/C move, B starts/pauses, A-long exits. Timer counts active play time, not pause. At most 15 stars/score max15; one bounded play_completed event after completion (no repeated completion on next frame). Cosmetic happy feedback only; no check-in credit, money or care mutation. Ghost disables game/pat-as-revival but retains Goal and Review. Network financial command arrival during game should exit/pause game consistently (choose exit to Pet) and play in-order; ordinary page navigation doesn't discard commands.

## Appearance and animation

Implement docs/MODULAR_ASSETS.md and docs/ANIMATION_ENGINE.md, including character-independent backgrounds, anchored clothing/variants, data-driven semantic clips, palette lookup, deterministic converter/preview and compiled registries. Those detailed revision2 requirements govern graphics behavior; final artwork only is deferred. Do not extend v1 JSON with background/outfit fields. Follow docs/ADDING_CONTENT.md for future art handoff.

Asset provider for pet_id piggy/cat/dragon; palette mint/coral/lavender; accessory none/cap/scarf; asset_version1. Art absent: draw placeholder shapes and text for each ID/state, never pretend final art exists. See docs/ASSET_CONTRACT.md. Renderer idle/blink, needs_checkin, sleepy, ghost; transient eating/traveling/celebrate/neutral/revive. Locally pat and cosmetic game feedback cannot emit a financial command/ack. Activity durations 2-10s from validated payload; defaults from contract. Persist cursor before each server-command animation start. Queue at most 4 pending plus separately identified active command; document capacity so redelivered response batch cannot duplicate or evict earlier commands. No repeated restart on state polls; commands ordered by seq with gaps allowed. Expired or ghost-suppressed commands are consumed in sequence. Unsupported animation skip is allowed only if the known v1 envelope/identity/seq/expiry/duration are structurally valid and the sole unknown is animation; record diagnostic, persist consumption. Other malformed batches rejected atomically, not partly executed. Unsupported api/asset version keeps old pet and requires update. Do not silently accept arbitrary enum drift elsewhere.

If care changes to ghost, stop/suppress ordinary activities, keep review available, clear old pending activities by ordered consumption. Revival only follows server-confirmed care and revive command. Preserve goal/identity. Ghost text: "I faded while we were away. Let's start fresh." No local authoritative decay; offline does not cause death. AM/PM completion and care/streak come from server. Review screen renders receipt.finance and receipt.goal, never substitutes a newer top-level summary beneath an older review_id.

## Protocol, JSON and time

HTTPS POST `/functions/v1/device-api/v1/sync`, Authorization Bearer opaque device token, JSON UTF-8, no-store. One request in flight. UUID IDs, integer cents, UTC Z timestamps, exact enums/nullability/ranges/additionalProperties from schemas. HTTP body <=4096 bytes request and <=8192 bytes response. Bound decoding depth and allocation; validate lengths before copying. Reject overflow/fractional integers, NaN, malformed dates, missing keys, unexpected keys, excessive nesting and malformed JSON. Read responses incrementally with cumulative cap, even chunked/unknown length; don't call unbounded getString first. Treat HTTP200 containing an error/HTML as invalid. Apply validated responses atomically. Match request_id/epoch, don't roll back state_version or financial snapshot. Check returned event IDs belong to outstanding actions and ack results don't remove unrelated entries.

Epoch-null bootstrap: ack0/events[], commands must be empty. Persist returned epoch safely, then regular sync. Cold start with a valid saved epoch/cursor/outbox uses regular sync to preserve unacknowledged actions. Bootstrap only unpaired state/reset recovery, not every reboot. On 409 RESET_REQUIRED, stop old animation, clear old epoch commands/events/cursor and mark durable reset pending; bootstrap with epoch:null, ack0, events[]. Do not send current_epoch as a substitute for null bootstrap or relabel old events. Handle power failure between reset steps. Unexpected new epoch in a successful regular response is invalid (require deliberate reset path). For duplicate state_version still process valid fresh command/event results; state_version alone doesn't identify duplicate HTTP response. For stale lower version ignore the response atomically, retain unconfirmed events.

Outbox holds at most8 durable stable-ID actions; no silent eviction. When full show pending/full and reject new action locally; permit reviewing cached info without false confirmation. Persist before enqueue becomes externally visible; retries reuse exact event ID/payload. Terminal accepted/duplicate/rejected remove matching entries with a durable update; transient failure retains them. Match results to events actually submitted in the immutable active request, not newer outbox entries queued during that request. Reject unsolicited result IDs atomically. Event IDs random proper UUIDs using device RNG, not uptime alone. Avoid persisting/logging NFC identifiers. Cursor per command (not per frame/poll), config on change, cached authoritative state only when changed/rate limited; financial state and pending records must remain consistent across storage crash.

Use Preferences/NVS with a versioned compact snapshot or equivalent verified transactional journaling. Check all write return values. Multiple puts are not an atomic transaction. If using A/B generation records+checksum, test torn/corrupt writes and monotonic recovery. Never roll back a previously reported successful cursor commit and replay its command. If durable command/event state cannot be trusted, fail closed for starting new commands/submitting unknown actions, keep idle UI and show storage fault. Disallow networking from leaking stale state during recovery. Config reprovision invalidates old device-scoped epoch/outbox/cache safely. Host tests inject write failure at each boundary.

Poll30s; demo2s only in server demo_mode; actions coalesce and max1request/sec. Retry2,4,8,16,30,60s +0-20% jitter; respect Retry-After (seconds/date with trusted clock) and valid contract retry_after_ms. 401 stops until reprovision,403 permission fault stops automatic retry;400/422 bounded diagnostic no rapid retry,426 update required;429 honors delay,5xx/network backoff. No retry storm on disconnected Wi-Fi. Immediate actions cannot bypass backoff/429/auth stops. Reset retry counters on genuine success. Cap server-controlled scheduling values to protocol. Keep UIs alive during DNS/TLS/HTTP timeouts.

Use monotonic clock for local scheduling, rollover-safe arithmetic or 64-bit timer. UTC from validated platform time synchronization before TLS; never use an untrusted HTTP server_time to bypass certificate date checks. After valid HTTPS response anchor expiry calculations to server_time+monotonic elapsed. Host tests pin UTC; historical fixtures must not be compared to today's clock. If time confidence lost, do not start possibly expired financial commands; request fresh sync. Never disable TLS hostname/CA verification; pin a maintained trusted CA/bundle with refresh instructions, not a brittle leaf certificate. No automatic redirects with Authorization to another host. Production endpoint must be a valid https Supabase host/path provisioned for the team, no URL userinfo or arbitrary ports/redirect targets.

## NFC

PN532 hardware SPI; verify module switches externally. Initialize/read firmware version/SAM config via inspected APIs and finite polling. IRQ/RSTO unwired. Implement required NDEF scenario stickers and normal review per docs/NFC_DEMO_STICKERS.md. No UID/PAN storage/logging/HTTP, no payment APDUs or guessed Type2 classification. One action per presentation, rearm after confirmed absence500ms (errors not absence). The public library may need a narrowly scoped pinned/licensed adapter patch for metadata/readiness; do not invent APIs. Card fallback/button review always works; missing NFC cannot block display/network. Food/ride/savings stickers create demo events only with fresh authorized server mode and online health; no optimistic live financial animation. Review sticker always opens financial review. Current protocol enums remain unchanged.

## Provisioning and website integration

Companion team creates/registers owner device and returns device UUID + opaque secret once. Firmware never carries bank keys, Supabase service-role keys or user's website password/JWT. Produce docs/WEBSITE_HANDOFF.md listing required real routes, headers, schema files and smoke flow. Device is already paired by backend token ownership, not by a card UID. No BLE/captive portal/browser USB dependency for MVP.

Implement bounded USB serial provisioning protocol and Python CLI helper with hidden password/token prompts (pyserial as dev dependency). A deliberately selected USB port and explicit local provisioning session required; no automatic erase/flash port discovery action. Request JSON newline capped e.g.2048 bytes, fields version1, SSID,password,device_id,api_url,device_token. Choose exact keys once, document and test; validate UUID/token/host/lengths before writing. On failure retain old config atomically. Never echo secrets, use bounded acknowledgements with status/error code only; no secret-bearing CLI arguments, reports or history. Save minimal config to NVS (not encrypted/tamper-proof by default; don't claim otherwise). Factory reset needs explicit local confirmation, not random button press; wipes own namespace only. Reprovision authenticated device token by USB to recover401. Connect2.4GHz hotspot; bounded Wi-Fi/SNTP retry, show setup/offline state rather than hanging boot. Don't wait indefinitely for Serial.

## Non-goals / physical limits

No final sprite design, production banking, new backend, website UI, account invites, AI API, arbitrary user-art rigging, OTA, audio files, battery gauge, motor or charge-and-run control. There is no battery ADC wire, so do not fabricate battery percentage or code charger control. Hardware must be tested by a person with USB-only bring-up and existing battery isolation procedure.
